2. ROLES DE HTML, CSS Y JAVASCRIPT EN RUEDA LIBRE
--------------------------------------------------
- HTML (Lenguaje de marcado): Define la estructura y el contenido semántico del sitio web (encabezados, párrafos, tablas, imágenes, listas y enlaces).
  Ejemplo: <h1>Rueda Libre</h1>
- CSS (Hojas de estilo en cascada): Controla la presentación visual, colores, tipografía, diseño adaptativo y disposición de los elementos.
  Ejemplo: header { background-color: # green; color: white; }
- JavaScript (Lenguaje de programación): Aporta interactividad dinámica y lógica en el lado del cliente (validación de formularios, filtros interactivos).
  Ejemplo: Evento para calcular automáticamente la tarifa total según las horas seleccionadas.

1. HOJA DE ESTILOS EXTERNA Y HERENCIA (MINIRETO 9)
--------------------------------------------------
- Se creó css/styles.css y se enlazó en las tres páginas (index.html con "css/styles.css"; paginas/tarifas.html y paginas/reservas.html con "../css/styles.css").
- Se cargaron Montserrat (700) y Open Sans (400, 600) desde Google Fonts con preconnect, antes del enlace a styles.css.
- Variables declaradas en :root: 5 colores de marca, --fuente-titulos, --fuente-texto (ambas con fuente de respaldo) y una escala de espaciado de 4 tamaños en rem (--espacio-sm/md/lg/xl).
- font-family, color y background-color se aplicaron una sola vez en <body>; el resto de elementos de texto (p, li, etc.) los heredan sin volver a declararlos.

Comprobación de herencia (DevTools: Styles / Computed) en un <p> dentro de <main>:
- Propiedad que SÍ se hereda: "color". El párrafo no tiene una regla propia de color; en el panel Computed aparece el mismo valor que <body> (var(--azul-noche) = #14213D), heredado por la cascada de herencia normal de las propiedades de texto.
- Propiedad que NO se hereda: "background-color". Aunque <body> define background-color: var(--crema), el <p> aparece en Computed con background-color: rgba(0, 0, 0, 0) (transparente): esta propiedad no es heredable por especificación CSS, por lo que el párrafo deja ver el fondo de su contenedor en vez de copiar el valor del body.

2. CONFLICTO DE ESPECIFICIDAD EN EL MENÚ (MINIRETO 10)
--------------------------------------------------
Reglas en conflicto:
  #menu a { color: var(--gris-asfalto); }
  .activo { color: var(--verde-ruta); font-weight: 600; }

Cálculo de especificidad (id, clase, elemento):
  - #menu a   -> 1 id + 0 clases + 1 elemento = (1,0,1)
  - .activo   -> 0 id + 1 clase  + 0 elementos = (0,1,0)

Causa del problema: un selector de id siempre pesa más que cualquier cantidad
de clases, sin importar el orden en que aparezcan las reglas en el archivo.
Por eso, aunque .activo se escriba después en la hoja de estilos, #menu a
(1,0,1) le gana a .activo (0,1,0) y el enlace de la página activa se queda
en gris (--gris-asfalto) en vez de verde (--verde-ruta).

Corrección (sin !important ni estilos en línea): se agregó la regla
"#menu a.activo { color: var(--verde-ruta); border-bottom: 2px solid var(--verde-ruta); }",
con especificidad (1,1,1). Al combinar el id, la clase y el elemento en un
solo selector, su especificidad supera a la de "#menu a" (1,0,1) y el enlace
activo vuelve a mostrarse en verde con un subrayado adicional.

3. MEDICIÓN DEL ANCHO DE UNA TARJETA CON BOX-SIZING (MINIRETO 11)
--------------------------------------------------
Tarjeta de servicio (.servicios article): flex-basis 16rem (256px),
padding: var(--espacio-md) = 1rem (16px) en cada lado, border: 1px en cada lado.

- Con box-sizing: content-box (valor por defecto del navegador): el padding
  y el borde se SUMAN al ancho de contenido de 256px.
  Ancho total = 256 + (16*2) + (1*2) = 256 + 32 + 2 = 290px.
- Con box-sizing: border-box (el aplicado en el sitio, mediante el selector
  universal "*, *::before, *::after { box-sizing: border-box; }"): el padding
  y el borde quedan INCLUIDOS dentro de los 256px.
  Ancho total = 256px (el contenido interno se reduce a 256 - 32 - 2 = 222px
  para dejar espacio al padding y al borde).

Verificado en DevTools (Computed): con border-box, el "Ancho renderizado" de
la tarjeta coincide con el valor de flex-basis que se definió en el CSS, en
vez de crecer por el padding y el borde como ocurría con content-box.

4. MAPA DE USO DE COLOR APLICADO EN CSS (MINIRETOS 9-11)

BITÁCORA DE PRUEBAS Y DECISIONES - RUEDA LIBRE v1.5 (DÍA 4: SEMANA 2)
==================================================

1. ENCABEZADO Y PIE CON FLEXBOX (MINIRETO 1)
--------------------------------------------------
Se convirtió <header> en un contenedor flex (display: flex;
justify-content: space-between; align-items: center; flex-wrap: wrap) con
dos hijos: el nombre/logo del negocio en un extremo y el <nav> en el otro,
alineados verticalmente entre sí. El menú (#menu) ya era flex desde el
MiniReto 10, así que solo se le agregó flex-wrap: wrap para que sus
enlaces bajen de línea en vez de desbordarse, y se le quitó cualquier
margen residual (ya no dependía de margin ni de inline-block).

El <footer> se reestructuró en tres bloques (marca, contacto, horario)
dentro de un contenedor .pie-contenido con display: flex; flex-wrap: wrap;
justify-content: space-between; align-items: flex-start; gap, y cada
bloque usa flex: 1 1 12rem para repartirse el espacio sin quebrarse en
columnas desiguales.

Prueba al estrechar la ventana (DevTools, modo responsive):
- Desde el ancho completo hasta ~700px, el nombre y el menú permanecen en
  la misma fila (extremos opuestos); por debajo de ese punto el espacio ya
  no alcanza para los tres enlaces del menú en una sola línea y, gracias a
  flex-wrap: wrap, el menú pasa a dos líneas sin que el encabezado se
  desborde ni se superponga con el nombre del negocio.
- El pie se comporta igual: los tres bloques (marca, contacto, horario)
  se ven en una sola fila hasta que el ancho disponible por bloque cae por
  debajo de ~12rem (192px); a partir de ahí, flex-wrap: wrap los apila en
  columna, uno debajo del otro, manteniendo la separación uniforme (gap)
  entre ellos.
- En ningún punto aparece scroll horizontal: flex-wrap siempre reorganiza
  el contenido hacia abajo en vez de desbordarlo hacia los lados.

2. LA FLOTA EN CUADRÍCULA (MINIRETO 2)
--------------------------------------------------
Se agregó la sección "Nuestra flota" en index.html con los 7 modelos del
negocio (Urbana Clásica, Urbana Plegable, Montaña Trail, Gravel Aventura,
Eléctrica Urbana, Infantil y Tándem), cada uno como un <article> con
imagen, nombre, descripción, precio por hora y un enlace "Reservar".

Nota de contenido: el repositorio solo cuenta con una fotografía de
bicicleta (img/bicicleta.jpeg); se reutilizó esa misma imagen en los 7
modelos en vez de inventar fotos distintas, y cada <img> tiene su propio
texto alternativo describiendo el modelo correspondiente para no perder
la información de accesibilidad.

.flota usa display: grid con grid-template-columns: repeat(auto-fit,
minmax(15rem, 1fr)) y gap, así que el número de columnas depende solo del
ancho disponible, sin ninguna media query. Dentro de cada tarjeta,
display: flex; flex-direction: column deja el enlace "Reservar" siempre
al final (margin-top: auto en el enlace), aunque las descripciones tengan
longitudes distintas.

Columnas observadas (cálculo a partir de la fórmula del grid, ya que
<main> tiene max-width: 60rem/960px, padding de 1rem por lado, tarjetas
con minmax(15rem, 1fr) = 240px mínimo y gap de 2rem/32px):
- Se necesitan aproximadamente 272px de ancho disponible por cada columna
  adicional (240px de tarjeta + 32px de separación).
- A 1280 px de ventana: el ancho útil de <main> queda topado en 960px -
  2rem de padding = 928px → entran 3 columnas (3×240 + 2×32 = 784px,
  caben; una 4ª columna necesitaría 1056px, no cabe).
- A 900 px de ventana: el ancho útil es 900 - 2rem = 868px → también 3
  columnas (784px ≤ 868px < 1056px).
- A 500 px de ventana: el ancho útil es 500 - 2rem = 468px → solo 1
  columna (2 columnas necesitarían 512px, no caben), cada tarjeta ocupa
  todo el ancho con flex: 1fr.
El séptimo modelo (Tándem) se agregó sin tocar una sola línea de CSS: la
cuadrícula simplemente reorganiza sus columnas para incluirlo.

3. LAYOUT EN DOS DIMENSIONES: GRID + FLEXBOX (MINIRETO 3)
--------------------------------------------------
Se construyó el layout de escritorio combinando Grid y Flexbox según si
cada caso necesitaba una o dos dimensiones. Decisión y justificación para
cada uno de los seis casos:

- Encabezado (header): Flexbox. Es una sola fila (una dimensión): nombre
  del negocio en un extremo, menú en el otro, centrados verticalmente con
  align-items.
- Pie de página (.pie-contenido): Flexbox. También es una sola fila de
  tres bloques (marca, contacto, horario) con separación uniforme; no
  necesita control por filas y columnas a la vez.
- Portada (.portada): Grid. Aquí sí hay dos dimensiones reales: columnas
  (texto 3fr / foto 2fr) y alineación vertical del contenido dentro de esa
  franja (align-items: center). grid-template-columns con fr reparte el
  espacio proporcionalmente sin medidas fijas.
- Galería "Nuestras rutas" (.galeria-rutas): Flexbox. Es una sola fila de
  tres tarjetas que se reparten el espacio con flex: 1; no hay necesidad
  de definir filas, así que basta una dimensión.
- Reservas (.reservas-layout): Grid. El formulario y la información de
  contacto deben quedar en proporción 2:1 como columnas definidas
  (grid-template-columns: 2fr 1fr), con el contenido de cada una
  alineado desde arriba (align-items: start) aunque tengan alturas
  distintas; es un caso de dos columnas con control explícito de ancho.
- Fila del formulario (.fila-formulario, documento + celular): Flexbox.
  Es una sola fila de dos campos cortos que se reparten el espacio con
  flex: 1 1 10rem y bajan de línea con flex-wrap si no caben; no hace
  falta una cuadrícula para dos elementos en una fila.

Criterio general aplicado: si el problema es "repartir elementos en una
fila o columna", se usó Flexbox (una dimensión); si el problema es
"definir filas Y columnas a la vez, con proporciones específicas entre
ambas", se usó Grid (dos dimensiones).

El menú, la cuadrícula de la flota y la validación nativa del formulario
se revisaron después de estos cambios y siguen funcionando igual que
antes: ninguno de los selectores nuevos entra en conflicto con los ya
existentes.

Se reorganizó styles.css para que los estilos base (fuera de cualquier
media query) describan la versión móvil en una sola columna, y se
agregaron dos puntos de quiebre con min-width: 768px (tablet) y 1200px

Problemas responsive encontrados y cómo se resolvieron (probados con el
modo dispositivo a 360px, 768px y 1280px):
1. Problema: en 360px, el encabezado con nombre y menú en la misma fila
   (como en el MiniReto 1) deja muy poco espacio para los tres enlaces
   del menú, que terminan apretados o truncados.
   Solución: mobile-first, el header empieza en columna (nombre arriba,
   menú debajo, centrado) y solo pasa a fila con justify-content:
   space-between desde 768px.
2. Problema: la cuadrícula de la flota, el layout 2:1 de reservas y la
   portada a dos columnas (pensados para escritorio) dejan columnas de
   menos de 150px de ancho en un celular de 360px, con el texto e
   imágenes aplastados.
   Solución: todos esos contenedores inician en una sola columna
   (grid-template-columns: 1fr o flex-direction: column) y solo adoptan
   su distribución de columnas desde 768px o 1200px según el caso.
3. Problema: las imágenes con atributos width fijos (logo, bicicleta,
   ruta) se salían de su contenedor o forzaban scroll horizontal en
   pantallas angostas.
   Solución: regla global img { max-width: 100%; height: auto; } y
   eliminación de los atributos width="..." del HTML; el logo usa ahora
   una clase .logo con max-width: 10rem en vez de un ancho fijo.
4. Problema: las tablas de tarifas.html, con el mismo relleno y tamaño
   de letra que en escritorio, obligaban a desplazarse de lado en un
   celular de 360px.
   Solución: th/td inician con relleno y letra reducidos (0.4rem 0.5rem,
   0.85rem) en móvil y crecen por etapas en los dos puntos de quiebre
   (0.5rem 0.75rem/0.95rem en tablet, y el relleno y tamaño originales
   en escritorio desde 1200px).

La v1.5 fue probada en el modo dispositivo de DevTools a 360px (una sola
columna, sin scroll horizontal en ninguna sección ni tabla), 768px
(encabezado en fila, portada a dos columnas, galería de rutas en fila,
reservas en proporción 2:1) y 1280px (mismo layout de tablet, con más
separación entre tarjetas y tablas a tamaño completo).

- La v1.5 usaba auto-fit/minmax, así que el número de columnas se

  Rueda Libre habría que sobrescribirlo con CSS propio o variables de

2. SIN UNA LÍNEA DE CSS: UTILIDADES (MINIRETO 6)
--------------------------------------------------
En la misma página de pruebas, debajo de la flota, se construyó la

casco y candado incluidos, guías certificados, puntos de devolución) y
la franja final "¿Listo para rodar?" con su enlace a reservas, usando

ninguna clase inventada por fuera de Bootstrap 5.3.

La franja pasa de columna (d-flex flex-column) en móvil a fila
(flex-md-row) desde el breakpoint md, con los elementos alineados con
justify-content-between/align-items-center y separados con gap-4 (sin
margin ni padding manual entre ellos). El elemento decorativo (una foto
circular) usa d-none d-md-block: no existe en el DOM visualmente en
móvil y aparece desde md. El enlace de la franja se destacó únicamente

rounded-pill), sin el componente .btn, que el MiniReto 6 pide dejar para
mañana.

Cinco clases consultadas en la documentación oficial de Bootstrap 5.3
(https://getbootstrap.com/docs/5.3/utilities/) y qué hace cada una:
1. fs-1: fija el tamaño de fuente al nivel 1 de la escala tipográfica de
   Bootstrap (el más grande, usado aquí para los íconos de cada
   beneficio), sin tocar font-size a mano.
2. text-bg-success: utilidad combinada que aplica a la vez el color de
   fondo "success" y un color de texto con contraste adecuado sobre ese
   fondo (evita calcular el contraste manualmente, como sí se hizo a
   mano con los colores de marca en la v1.0).
3. rounded-pill: redondea los bordes al máximo (forma de píldora),
   pensada para botones o enlaces destacados como el de "Reservar ahora"
   en la franja.
4. gap-4: aplica gap (separación entre elementos flex/grid) usando la
   escala de espaciado de Bootstrap, equivalente a lo que en CSS propio
   se escribió a mano con la variable --espacio-lg.
5. d-none / d-md-block: pareja de utilidades de display responsive;
   d-none oculta el elemento por defecto (display: none) y d-md-block lo
   vuelve a mostrar (display: block) desde el breakpoint md, sin
   necesidad de escribir una media query propia.

  0-0-1) también alcanzaba a .form-check-label, obligándolo a quedar
  en bloque y rompiendo el layout en línea que Bootstrap espera para
  los radios (label al lado del círculo, no encima).
- input[type=...] (0-0-1-1, un atributo más una etiqueta) le ganaba a
  .form-control (0-0-1-0) en los inputs de texto, pero select y
  textarea (0-0-0-1, sin atributo) perdían contra .form-select y
  .form-control (0-0-1-0) — el resultado era un formulario con bordes
  y relleno inconsistentes entre tipos de campo, cada uno mezclando
  reglas de dos sistemas distintos.
- button[type=submit] (0-0-1-1) competía de la misma forma con
  .btn/.btn-primary.
Se resolvió eliminando las tres reglas heredadas de la semana 1 y
dejando que los componentes de formulario y botón de Bootstrap
controlen el 100% del estilo (documentado con un comentario
NOTA/CONFLICTO en el propio css/styles.css, siguiendo el mismo patrón
usado en los conflictos de los MiniRetos 7 y 8). No fue necesario
ningún !important: bastó con no competir.

4. IDENTIDAD DE MARCA SOBRE BOOTSTRAP (MINIRETO 12)
--------------------------------------------------
Se sobrescribieron las variables CSS propias de Bootstrap (sección "1c.
IDENTIDAD DE MARCA SOBRE BOOTSTRAP" de css/styles.css) en vez de pelear
contra la cascada con selectores más específicos:
--bs-primary y --bs-primary-rgb (Marrón Ruta), --bs-body-font-family
(la tipografía de texto del proyecto), --bs-link-color/-rgb y
--bs-link-hover-color/-rgb (Marrón Ruta / Negro Noche) y
--bs-border-radius (0.5rem, menos redondeado que el valor por defecto
de Bootstrap, acorde al resto del sitio).

Se creó una variante propia de botón, .btn-terracota, usando las
variables --bs-btn-* por componente (sin !important): fondo Terracota
Pedal con texto negro en reposo (~4.8:1 de contraste, cumple WCAG AA
para texto normal) y fondo Negro Noche con texto blanco en
hover/active (~18:1). Se probó primero texto blanco sobre Terracota
Pedal en reposo y se descartó: solo da ~4.3:1, por debajo del mínimo
4.5:1 para texto de tamaño normal.

Se agregaron 3 clases propias complementarias (sección "7. CLASES
PROPIAS COMPLEMENTARIAS"): .portada-destacada (panel sutil con el
color de marca al 6% de opacidad sobre la sección de "¿Quiénes
somos?"), .seccion-titulo (línea Terracota Pedal de 3px bajo cada
título de sección, con una variante centrada para los títulos que usan
text-center) y .pie-marca (fondo Negro Noche con texto Crema en el
<footer>, reemplazando el pie claro que tenía desde la semana 1).

Se agregó Bootstrap Icons 1.11.3 por CDN en las tres páginas,
cargado entre bootstrap.min.css y styles.css. Se usó en: los
tres enlaces del navbar (bi-house-door, bi-tags, bi-calendar-check),
los 4 íconos de "¿Por qué Rueda Libre?" (antes emoji 🔧🪖🧭📍, ahora
bi-tools/bi-shield-check/bi-compass/bi-geo-alt), "Encuéntranos"
(bi-geo-alt-fill, bi-envelope-fill) y el pie de página

de WhatsApp, que ahora es un ícono sin texto (bi-whatsapp dentro de un
botón circular), lleva aria-label="Escríbenos por WhatsApp" en su

BUG DE CONTRASTE ENCONTRADO Y CORREGIDO: al oscurecer el fondo del

RESUMEN DE LA SEMANA
--------------------------------------------------
La semana 2 tomó el sitio estático de la semana 1 (v1.0) y lo llevó
por dos caminos complementarios: primero CSS propio responsive
(Flexbox, Grid, mobile-first con media queries — v1.5), después una
migración completa a Bootstrap 5.3.3 (grilla, utilidades, componentes
— v2.0-beta) y finalmente la aplicación de la identidad de marca sobre
ese framework (navbar, carrusel, formulario validado, alerta, modal e
iconografía — v2.0). En cada paso se documentó qué CSS propio se pudo
eliminar por quedar redundante con Bootstrap, y qué conflictos de
especificidad aparecieron al mezclar ambos sistemas — ninguno se
resolvió con !important; todos se resolvieron entendiendo el orden de
carga, la cascada o las variables --bs-* de cada componente.

MAPA DE CONSTRUCCIÓN DEL PRODUCTO FINAL
--------------------------------------------------
Los MiniRetos 1 a 4 construyeron la estructura y el contenido de las
tres páginas. Los MiniRetos 5 a 8 les dieron semántica, un formulario
validado y accesible, y migraron el layout completo a la grilla y las
utilidades de Bootstrap (v2.0-beta). Los MiniRetos 9 a 12 completaron
la migración de componentes (navbar, carrusel, formulario, alerta,
modal) y aplicaron la identidad visual de marca sobre las variables de
Bootstrap, sin crear archivos aislados: cada reto siguió modificando
los mismos tres archivos HTML y el mismo css/styles.css. El resultado
es Rueda Libre v2.0: un sitio de una sola hoja de estilos propia,
cargada después de Bootstrap para que su identidad de marca gane la
cascada sin !important, con todos los componentes interactivos
(navbar colapsable, carrusel, validación de formulario, alerta
descartable, modal) funcionando con el JavaScript propio de Bootstrap,
sin una sola línea de JavaScript escrita a mano.
